# 作曲の作法

ゲームの BGM と効果音を書くときの決まりと目安です。曲は `games/<ゲーム名>.js` にデータで書きます。

## 進め方

1. 方向（音色・テンポ・雰囲気）の違う候補を 3〜4 曲作る
2. `npm run lint:songs` で和声の書き間違いを、`npm run measure -- --parts --out <フォルダ>` で音量の釣り合いを確かめる
3. 試聴ページで、ユーザーに聞いてもらう。主旋律の楽器は、試聴ページの選択欄で替えて聞き比べられる（曲のデータの `melody` に、主旋律のパートの名前を書く）。不満は「区間と小節」（例：B の 3 小節目）で受け取る。試聴ページは再生中の区間と小節を表示し、区間を押すとそこから鳴る
4. 直して、また計測と試聴。決まったら、ゲームのセッションに知らせて同期する

作った側は音を聞けない。聞けない分は、計測の数値（音量・パートの釣り合い・スペクトログラムの画像）と、和声の検査で補う。確認のためにブラウザで鳴らすときは、Chrome を `--mute-audio` で起動する（`tools/chrome.mjs` は既定でそうする。ヘッドレスでも音はスピーカーから出る）。

## 曲の構成

- **イントロ（1回だけ）＋ループ**。ループは 80〜120 秒（16〜60 小節）。パズルを考えながら長く聞くので、短いループ（mine-blocks の旧 BGM は 13 秒）はすぐ飽きる
- 区間は A（主題）・A'（終わりを変えたもの）・B（和音の流れを変える）・C（休憩：ドラムとメロディを減らす）くらい。例：`A A' B C A A'`
- **同じものを繰り返すときは、何かを足すか引く**（2回目の A に対旋律を足す、B でドラムを半分にする、など）。区間ごとの音量は 1〜3dB 動くのがよい（計測の「区間」）
- イントロは伴奏だけで 4 小節ほど。ループの頭（A）へ自然につながるように、最後の小節を属和音（V）にする
- **ループのつなぎ目**：ループの最後の小節は、最初の和音へ進む和音にする（V → I、または IV・vi への偽終止）。最後の小節の終わりに、ループの頭の音へ向かう短い経過音を置くと、切れ目が目立たない。リバーブの余韻は、ループの頭にそのまま重なる

## パートの役割と音域

| パート | 役割 | 音域の目安 | 楽器の例 |
|---|---|---|---|
| メロディ | いちばん目立つ。歌えるくらいの動き | A4〜D6（チップは C5〜F6） | marimba・chip・softLead |
| 対旋律・ベル | メロディが伸ばしている所や休みに、短く答える | C5〜F#6 | bell・chip（duty 0.5） |
| 伴奏 | 和音を刻む・分散する | C4〜E5（メロディより下） | marimba（arp）・epiano（chords）・pluck（arp） |
| パッド | 和音を薄く敷く。B・C で足す | A3〜D5 | pad |
| ベース | 和音の根音。スマホではほぼ聞こえないので、メロディに頼る | C2〜C4（octave 2） | pluck・synthBass・chip（三角波） |
| ドラム | 拍を示す。うるさくしない | — | drums（soft・chip） |

- メロディと伴奏の音域を重ねない。重なると、メロディが埋もれる
- 長く伸ばす音は、メロディと伴奏で **半音（短9度を含む）にしない**（`lint:songs` の「ぶつかり」）。7th の和音の上で、メロディが根音、伴奏が長7度を下で鳴らす形も避ける
- メロディの長めの音（8分音符以上・拍の頭）は、和音の構成音か、9th などの響く音にする（`lint:songs` の「避けたい音」：構成音の半音上の音）

## うるさすぎないために

- 16 分音符で動くパートは、1曲に1つまで。休憩の区間（C）では、分散和音をゆっくりにするかドラムを抜く
- 1秒あたりの音の数は、メロディで 1〜2.5、全体で 15 前後まで（`lint:songs` の「音/秒」）
- 4kHz より上の割合は 6% まで（`measure` の「4kHz以上」）。チップの細い矩形波（duty 0.125）や高いベルは、長く伸ばさない
- リバーブとエコーで、素朴な音色にも広がりを出す（送りの量は 0.1〜0.35）。エコーは付点8分（`time: 0.75`）が拍とぶつかりにくい

## 音量の目安

パートを1つずつ鳴らしたときの、全体との差（`measure --parts`。括弧はスマホ相当、250Hz より下を削った値）：

| パート | 全体との差 |
|---|---|
| メロディ | -2〜-3dB（スマホでも -1.5dB 以内） |
| 伴奏（エレピ・マリンバの分散和音） | -5〜-8dB |
| 対旋律・ベル | -6〜-9dB |
| ベース | -6〜-7dB |
| ドラム | -8〜-11dB |
| パッド | -12〜-14dB |

- ベースは全体の音量を食いやすい（最初の版では、どの曲もベースが全体と同じ大きさだった）。音量計の数値は低音で大きく出るが、スマホでは聞こえない。メロディが小さく聞こえる原因になる
- 曲全体は、`gain` で **-39 LUFS**（`measure` の LUFS。ゲームの既定の音量 master 0.8・bgm 1 で）にそろえる。mine-blocks の旧 BGM と同じ大きさ。曲ごとの差は 1dB 以内にする
- 効果音は、よく鳴る音ほど小さくする（瞬間 LUFS の目安：選ぶ・置く・外す・時計は -40〜-55、置けない・開始は -37、+20秒・降参・負け・時間切れは -28、クリア・優勝は -23）
- 楽器の既定の音量は、`volume: 1` でおおよそ釣り合うようにしてある（4音の和音は 0.3〜0.5 にする）
- ピークは -1dBFS より下。全体の出口にリミッター（-3dB）があるが、頼らない
- **矩形波（チップ）は、同じ LUFS でも大きく聞こえる**（耳に敏感な 2〜5kHz に倍音が多い）。試聴ページの楽器の一覧を同じ LUFS にそろえたところ、チップだけ「大きすぎる」と言われたので、一覧でも主旋律の差し替えでも 5dB 小さくする補正を入れている（`audition/instruments.js` の楽器ごとの `trim`。ハープとはじく弦も、大きく聞こえると言われて -3dB にした）。曲の中でチップをほかの楽器と並べるときも、数値より 5dB ほど小さめにする

## 記法

長さは 16 分音符の数（4 で 4 分音符、16 で 1 小節）。省くと前の音と同じ長さになる。`|` は小節の区切りで、長さが合わないとエラーになる。並びが区間より短ければ、区間の終わりまで繰り返す。

```js
parts: {
    lead: { instrument: 'marimba', volume: 1, pan: -0.15, reverb: 0.2, delay: 0.1 },          // 音符をそのまま書く（mode: 'notes'）
    bass: { instrument: 'pluck', mode: 'bass', octave: 2 },                                    // 和音から根音・度数
    comp: { instrument: 'marimba', mode: 'arp', from: 'C4' },                                  // 分散和音
    keys: { instrument: 'epiano', mode: 'chords', center: 'E4', voices: 4 },                   // 和音の刻み
    drums: { instrument: 'drums', kit: 'soft', mode: 'drums', levels: { hat: 0.6 } }           // ドラム
},
sections: {
    A: {
        chords: 'F | C/E | Dm7 | A7sus4:8 A7:8',            // 1小節ずつ。1小節に2つなら等分か、長さを書く
        lead: 'A4:2 C5 F5:3 E5:1 r:2 [C5,E5]:4 C5~G5:2 E5:2@0.6 | ...',   // r 休み、[ ] 和音、~ 滑らせる、@ 強さ
        bass: 'R:4 r:2 R:2 5:2 r:2 R+:2 5-:2',              // R 根音（分数和音なら指定の低音）、3・5・7・9 度数、+ - でオクターブ
        comp: '0:2 1 2 1 3 1 2 1',                           // from より上の構成音の何番目か
        keys: 'x-----x---x-----',                            // x で鳴らし、- で伸ばす、. は休み（X 強く・o 弱く）。'hold' は和音ごとに伸ばす
        drums: { kick: 'x.....x...x.....', snare: '....x.......x...', hat: 'xoxoxoxoxoxoxoxo' }
    }
}
```

3拍子は `stepsPerBar: 12` と書く（1ステップは16分音符のまま。ドラムや和音の刻みも1小節12文字）。

候補の曲は、1曲ずつ `games/<ゲーム名>.<曲名>.js` に書いて並行で作れる（`SoundKit.register('<ゲーム名>', { songs: { <曲名>: ... } })`。同じ名前の登録は足し合わされる）。`node tools/lint-songs.mjs <ファイル>` で、そのファイルだけを検査できる。

曲の項目：`title`・`description`・`bpm`・`gain`・`swing`（裏拍を遅らせる割合、0〜0.2）・`swingUnit`（1：16分、2：8分）・`humanize`（`{ time: 秒, velocity: 割合 }`。わずかなばらつき）・`reverb`（`{ seconds, tone }`）・`delay`（`{ time: 拍, feedback, tone, reverb }`）・`intro`・`loop`。

パートの項目：`instrument`・`mode`・`volume`・`pan`・`reverb`・`delay`（送りの量）・`cutoff`（ローパス）・`chorus`・`autopan`・`gate`（音の長さの割合）・`humanize: false`、ほかに楽器ごとの設定（`chip` の `wave`・`duty`・`vibrato`、`pluck` の `brightness` など。`src/sound-kit.js` の INSTRUMENTS）。

効果音は層の配列で、`{ instrument, notes, unit（長さ1つの秒数）, at（始まりの秒）, volume, pan, reverb }`。`notes` は上と同じ記法で、`1200hz` のように周波数も書ける。ドラムは `kick:1 r:2 openHat:1` のように名前で書く。
